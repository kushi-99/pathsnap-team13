## 1. Model Loading Procedure

Load `MLPPredictor` **once at FastAPI application startup** (inside a FastAPI `lifespan` context manager) and reuse the singleton across all requests. Do **not** reload weights or the scaler inside request handlers.

```python
from contextlib import asynccontextmanager
from pathlib import Path
from fastapi import FastAPI
from ml.mlp.predict import MLPPredictor

predictor: MLPPredictor | None = None

@asynccontextmanager
async def lifespan(app: FastAPI):
    global predictor
    predictor = MLPPredictor.from_artifacts(
        artifacts_dir=Path("ml/mlp/artifacts"),
        device="cpu",
    )
    yield
```

`MLPPredictor.from_artifacts()` loads weights with `torch.load(..., map_location="cpu", weights_only=True)`, switches the model into `eval()` mode (disabling Dropout and using frozen BatchNorm running statistics), and loads the exact `StandardScaler` fitted on the 80 training trips.

## 2. Required Model Artifacts

All five files must be co-located in `ml/mlp/artifacts/` (default path):

| Artifact File | Format | Purpose |

| `scaler.joblib` | Joblib (`StandardScaler`) | Z-score feature scaler fitted strictly on the 80 `train` trips |

| `label_mapping.json` | JSON | Binary class mapping (`{"0": "non_match", "1": "match", "positive_class": 1}`) |
| `model_config.json` | JSON | `MLPConfig`, `CandidateConfig`, parameter count (`14,529`), random seed (`42`), epoch budget (`6`) |

*(Optional provenance file `training_metadata.json` is also stored in the same directory for auditability.)*

During final two-laptop evaluation, Laptop 2 sends `{"trip_id": "<eval_trip_id>"}`. ## 4. Output JSON Structure (Preserving Candidate ↔ Arc Mapping & HMM Compatibility)

See actual verified output in [sample_response.json](file:///c:/Users/Admin/Downloads/ML%20HACKATHON/api_integration/sample_response.json):

```json
{
  "trip_id": "00000000",
  "model_name": "mlp_128_64_32",
  "num_observations": 2,
  "num_candidates": 14,
  "inference_time_ms": 55.559,
  "predicted_arc_ids": [17630, 17630],
  "observations": [
    {
      "obs_idx": 0,
      "predicted_arc_id": 17630,
      "top1_match_prob": 0.970563,
      "top1_emission_prob": 0.994512,
      "candidates": [
        {
          "arc_id": 17630,
          "match_prob": 0.970563,
          "emission_prob": 0.994512,
          "log_emission_prob": -0.005503
        }
      ]
    }
  ]
}
```

### HMM / Viterbi Compatibility Guarantees
- Every observation entry explicitly maps `obs_idx -> candidates[]`, where every candidate preserves its exact original 0-based `arc_id` from `.arcs`.
- Three score forms are returned for downstream flexibility:
  1. `match_prob`: Raw sigmoid probability $P(y_{t,c}=1 \mid \mathbf{x}_{t,c}) \in (0, 1)$.
  2. `emission_prob`: Per-observation normalized distribution summing to `1.0` across all candidates of `obs_idx`.
  3. `log_emission_prob`: $\log(\max(\text{emission\_prob}, 10^{-12}))$, directly pluggable into additive log-space Viterbi dynamic programming.
- Candidates within each observation are sorted descending by `match_prob`, so `candidates[0]["arc_id"] == predicted_arc_id`.

## 5. Prediction Function Signatures

Defined in [ml/mlp/predict.py](file:///c:/Users/Admin/Downloads/ML%20HACKATHON/ml/mlp/predict.py):

```python
class MLPPredictor:
    @classmethod
    def from_artifacts(
        cls,
        artifacts_dir: Path = ARTIFACTS_DIR,
        device: str = "cpu",
    ) -> "MLPPredictor": ...

    def predict_candidates(
        self,
        candidates: Union[pd.DataFrame, Sequence[Mapping[str, Any]]],
        trip_id: Optional[str] = None,
    ) -> Dict[str, Any]: ...

    def predict_scores(
        self,
        candidates: Union[pd.DataFrame, Sequence[Mapping[str, Any]]],
    ) -> tuple[pd.DataFrame, np.ndarray, np.ndarray, np.ndarray, float]: ...

    def predict_trip_dir(self, trip_dir: Path) -> Dict[str, Any]: ...
```

- Use `predict_candidates()` for JSON/dict payloads or DataFrames returning the structured response dict.
- Use `predict_scores()` for zero-overhead vectorized NumPy arrays directly inside a high-throughput Python HMM/Viterbi loop.
- Use `predict_trip_dir()` for end-to-end inference directly from a raw trip folder (strictly ignores `.route`).

## 6. Preprocessing Requirements

1. **Exact feature column alignment:** `MLPPredictor` extracts columns in the exact order defined by `artifacts/feature_columns.json`. Extra columns (e.g., metadata) are ignored; missing required columns trigger `PredictionInputError`.
2. **Coordinate projection & units:** Distance features must be in **meters** (using per-trip local tangent-plane projection centered at the trip centroid, NOT raw degree Euclidean distance). Angles must be in radians/cosine/sine as specified in `data_adapter.py`.
3. **StandardScaler:** Applied internally inside `MLPPredictor` using the persisted `scaler.joblib` (fitted strictly on the 80 training trips). Callers must pass **unscaled raw physical features**.
4. **Finite values:** All feature inputs must be finite floats (`NaN` / `Inf` rejected explicitly).

## 7. Error Handling

| Failure Condition | Raised Exception / Recommended HTTP Status | Behavior |
|---|---|---|
| Missing artifact file at startup | `FileNotFoundError` (fail fast on startup) | Lists exact missing files in `artifacts_dir` |
| Empty candidate list / DataFrame | `PredictionInputError` → **HTTP 400** | Rejects request cleanly |
| Missing `obs_idx`, `arc_id`, or any required feature column | `PredictionInputError` → **HTTP 422** | Lists missing column names |
| `NaN` or `Inf` in any feature column | `PredictionInputError` → **HTTP 422** | Lists offending column names |
| Unknown `trip_id` (trip-level endpoint) | **HTTP 404** | Backend verifies trip folder exists before inference |
| Unexpected runtime error | **HTTP 500** | Log traceback server-side; return safe error detail |

## 10. Integration Instructions for the Backend Developer

1. **Install dependencies:** `pip install -r requirements_person4.txt` (ensure PyTorch CPU index is used if installing fresh: `pip install torch --index-url https://download.pytorch.org/whl/cpu`).
2. **Verify artifacts exist:** Confirm `ml/mlp/artifacts/` contains all 5 required files (`mlp_model.pt`, `scaler.joblib`, `feature_columns.json`, `label_mapping.json`, `model_config.json`).
3. **Wire `MLPPredictor` into FastAPI startup & route:**
   ```python
   from fastapi import FastAPI, HTTPException
   from ml.mlp.predict import MLPPredictor, PredictionInputError

   @app.post("/predict/candidates")
   def predict_candidates_endpoint(payload: dict):
       try:
           return predictor.predict_candidates(
               payload["candidates"], trip_id=payload.get("trip_id")
           )
       except PredictionInputError as exc:
           raise HTTPException(status_code=422, detail=str(exc))
   ```
4. **Connect to HMM/Viterbi:** Pass `result["observations"]` to the HMM decoder, reading `cand["arc_id"]` as hidden states and `cand["log_emission_prob"]` as emission log-probabilities.
5. **Preserve Server-Side Ground Truth:** On `POST /predict`, load `<eval_trip>.route` **only inside the server-side evaluation helper** to compute accuracy/F1/continuity metrics — never pass `.route` to `MLPPredictor` or include raw reference arcs in the HTTP response sent to Laptop 2.
6. **Enable LAN access & request logging for final evaluation:** Launch Laptop 1 with `uvicorn app.main:app --host 0.0.0.0 --port 8000` so Laptop 2 can reach `http://<LAPTOP_1_IP>:8000` and CMD logs clearly show incoming inference requests to evaluators.
